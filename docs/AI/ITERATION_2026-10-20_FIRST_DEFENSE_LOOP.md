# Iteration: First outpost-defense loop

- **Goal:** Turn the existing third-person Morrow District into a small playable tower-defense prototype while retaining the shooter weapon.
- **Acceptance criteria:** Spawn yellow enemies in waves on the three road approaches; reward kills; let the player spend credits on turret, guard bot, barbed wire, wall repair/reinforcement, ammo, and an airstrike; keep the existing shooter Blueprint as the configured game mode.
- **Change:** Added native zombie archetypes and wave management, basic colored deployable defenses, purchase actions on number keys 1–7, wall integrity upgrades, ammo refill integration, and project setup documentation.
- **Verification:** UE 5.8 `extractionFPSEditor` build succeeded. In Play In Editor the first wave announced six incoming zombies and pressing `1` visibly spawned a sentry. Hotkeys `2` (guard bot) and `3` (barbed wire) were confirmed in the earlier PIE run. On the rebuilt version, hotkeys `4` and `5` displayed their expected guard messages (outpost already full; airstrike costs 120), `6` successfully refilled ammo and reduced credits from 200 to 175, and `7` reinforced the wall and reduced credits to 95. Zombies reached and damaged the outpost, which fell from 100% to 0% during the short six-zombie test, showing that current damage is too high. The starter pistol now loads from its class cached in the character constructor; this fixed a runtime crash caused by calling `ConstructorHelpers::FClassFinder` in `BeginPlay`. D3D12 reset the GPU during Manny rendering, but rerunning the editor in DirectX 11 allowed PIE to start and the hotkey checks above. The level view is still too dark/washed to confirm the live yellow zombie material. The palette materials and skeletal-ready yellow material were generated and saved. Unreal MCP was not used.
- **Outcome:** Build and basic input paths are confirmed, but the first playable loop needs a balance pass: the outpost cannot survive the current six-enemy arrival. Ammo purchase updates successfully, though the HUD still visibly reads `0 | 0`, which needs investigation. The visual pass is not complete: runtime colors/lighting, zombie appearance, and detailed replacement models remain to be checked or built.
- **Reusable lesson:** Keep the existing Shooter Blueprint in the inheritance chain so its weapon, character and HUD assets remain active while native code adds the wave-defense rules.
- **Follow-up:** Slow incoming outpost damage so a first wave is survivable; verify ammo count and yellow zombies in a clear, well-lit view; inspect zombie approach on all three lanes; then develop detailed original zombie and defense models and improve deployable placement/HUD.
