# Yellow zombie and camera pass

- **Goal:** Begin replacing the geometric zombie with a detailed stylized model, preserve the required yellow readability, and bring the third-person battlefield camera closer to the play area.
- **Asset:** Hotstrike Studio, [Free Stylized Dark Fantasy Zombie](https://hotstrikestudio.itch.io/free-stylized-dark-fantasy-zombie). The free download contains one rigged 8,286-triangle mesh and PBR textures. The author permits use and modification in finished games, disallows repackaging/reselling as standalone content, and says credit is appreciated but not required. No animation clips are included; no generative AI was used.
- **Changes:** Imported the skeletal mesh, its skeleton, and the albedo texture as Unreal assets under `Content/Characters/Enemies/YellowZombie`. Created `M_Zombie_StylizedYellow`, which desaturates the source albedo and tints it yellow so the surface detail remains visible while the enemy reads as yellow. Updated `ATDZombieCharacter` to use the imported model and this material. Torso gear now finds a spine bone by name, so attachment does not depend on Manny's `spine_03` naming. The mannequin animation blueprint is only assigned when its skeleton matches; this asset needs retargeted idle/walk/attack clips before the moving enemies will animate.
- **Camera:** Reduced the spring-arm length to 650 cm and set the initial pitch to -48 degrees to move away from the almost-vertical framing.
- **Verification:** UE 5.8 C++ editor target compiled successfully after these changes. The content-only import commandlet imported the mesh, skeleton, textures and yellow material, and completed with zero errors; the importer warned that it repaired invalid FBX bind poses using the time-zero pose. A runtime validation of the main project is blocked: Windows Code Integrity events 3077 and 3033 show that policy ID `0283ac0f-fff1-49ae-ada1-8a933130cad6` rejects the unsigned `UnrealEditor-extractionFPS.dll`. The new camera and zombie are therefore not yet confirmed in PIE.
- **Earlier gameplay evidence:** In the prior standalone run, the sentry killed zombies, the outpost survived longer after damage was reduced, and the repair/ammo/purchase hotkeys showed expected success or affordability messages. Ammo's numeric HUD still displayed `0 | 0` after refilling. These checks predate the current mesh and camera changes.
- **Next:** Use an administrator-approved signed build path for the project module; set up and validate retargeted idle/walk/attack clips for the new rig; verify the yellow model and current camera in the Morrow map; fix the ammo HUD count; then test the airstrike against a group.
